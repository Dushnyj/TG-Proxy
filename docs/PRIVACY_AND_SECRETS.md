# Данные, приватность и секреты

## Что хранится на Android

- настройки сетевых профилей и маршрутов;
- MTProto secret локального listener;
- client tokens сохранённых Relay;
- только у владельца: SSH endpoint, подтверждённый host key, owner token, необязательный
  SSH-пароль и DuckDNS token;
- локальный installation ID и журналы диагностики.

Чувствительные значения сохраняются через Android Keystore-backed хранилище. Android backup
для приложения отключён; обычный экспорт и ссылка подключения не являются резервной копией
owner-доступа.

## Что передаётся

| Получатель | Данные |
| --- | --- |
| Telegram на телефоне | локальный адрес, порт и MTProto secret |
| выбранный upstream | Telegram tunnel и минимум метаданных маршрута |
| VPS Relay | client token, installation metadata, целевой разрешённый DC |
| GeoIP provider Relay | публичный IP устройства, только если владелец включил `geoIpUrl` |
| DuckDNS | имя, DuckDNS token и публичный IP VPS при настройке DuckDNS |
| GitHub | запрос проверки обновления и загрузка выбранного release asset |

GeoIP — приблизительные страна/город по публичному IP, не GPS телефона.

## Экспорт и передача

- ссылка и QR Relay содержат один client token;
- URL fragment не отправляется HTTP-серверу;
- owner token, SSH и DuckDNS credentials не включаются;
- перенос без секретов содержит настройки одного выбранного профиля без MTProto secret и Relay;
- защищённый паролем перенос содержит MTProto secret и одно основное Relay-подключение этого
  профиля, но не является резервной копией приложения;
- пул Relay, привязки остальных профилей, owner/SSH/DuckDNS и системные параметры не
  экспортируются;
- внешний импорт показывает preview и применяется только после подтверждения.

## Диагностика

TG Proxy маскирует raw Relay token и полный MTProto secret и не должен добавлять SSH-пароль в
отчёт. Но отчёт содержит технические сведения о сети, доменах, устройстве и маршрутах. Перед
публикацией просмотрите архив самостоятельно.

## Что нельзя коммитить или публиковать

- реальные SSH host/login/password;
- production IP и непубличные доменные имена;
- raw client/owner/DuckDNS/GitHub tokens;
- Android keystore и пароли подписи;
- приватные SSH/TLS/topology signing keys;
- production-конфиги и state-файлы;
- ADB backup, SharedPreferences, полные пользовательские логи;
- скриншоты с аккаунтом, IP, токеном или личным доменом.

Для кода и документации используйте `example.com` и адреса RFC 5737 (`192.0.2.0/24`,
`198.51.100.0/24`, `203.0.113.0/24`).

Правила закрытого сообщения об уязвимости: [SECURITY.md](../SECURITY.md).
