# Надежность

## Проблема

Android может остановить приложение в фоне, ограничить сеть или оставить UI в состоянии, которое не соответствует реальной работе сервиса. Из-за этого пользователь видит `Активен`, но Telegram не подключается, пока прокси не переподключить вручную.

## Источник истины

Источником истины должен быть foreground service, а не состояние кнопки на главном экране.

UI показывает `Активен` только если:

- сервис жив;
- локальный порт слушает;
- Route Engine имеет рабочий маршрут;
- последние проверки не показывают критический отказ.

Если одно из условий нарушено, UI показывает:

- `Переподключение`;
- `Нестабильно`;
- `Ошибка`;
- `Остановлен`.

## Foreground service

Требования:

- `START_STICKY`;
- постоянное уведомление;
- действия в уведомлении: `Остановить`, `Переподключить`, `Диагностика`;
- корректная остановка по команде пользователя;
- автоматический рестарт после системного убийства, если пользователь включил автозапуск.

## Watchdog

Watchdog проверяет:

- слушает ли локальный порт;
- принимает ли сервис подключения;
- не завис ли Route Engine;
- есть ли последние успешные handshake;
- идет ли трафик при активных подключениях;
- не ушел ли активный маршрут в серию timeout/429/reset.

Если найден сбой:

1. пометить состояние как `reconnecting`;
2. не трогать рабочие соединения без необходимости;
3. прогреть лучший fallback;
4. перевести новые подключения на рабочий маршрут;
5. обновить уведомление и диагностику.

## Network callback

При смене сети приложение не должно немедленно уничтожать текущие маршруты. Правильная логика:

1. обнаружить новую сеть;
2. выбрать или создать профиль;
3. проверить активный маршрут;
4. если маршрут не подходит, найти fallback;
5. сохранить результаты в профиль.

## Battery optimization

Постоянно включённый экран не гарантирует жизнь приложения: Android/MIUI может завершить
процесс, ограничить background launch или скрыть foreground notification независимо от
screen timeout. Поэтому после установки и после каждого обновления приложение проверяет и
показывает отдельные условия:

```text
Запуск после перезагрузки: включён / выключен пользователем
Foreground notification: разрешено / запрещено
Оптимизация батареи: без ограничений / ограничена
OEM-автозапуск: подтверждён пользователем / не подтверждён
```

На Android 13+ notification permission запрашивается отдельным системным диалогом. Исключение
из оптимизации батареи и экран автозапуска производителя открываются только по действию
пользователя. Android не предоставляет общего API чтения состояния Xiaomi/Oppo/Vivo
autostart, поэтому приложение хранит ручное подтверждение и дополнительно фиксирует, видел ли
`BootReceiver` реальную загрузку устройства. Нельзя показывать непроверяемый OEM-флаг как
системно подтверждённый.

Если пользователь отказал или ушёл из системных настроек без изменения, предупреждение не
исчезает: `Android или оболочка производителя могут остановить прокси`. Помощник можно открыть
повторно в `Настройки -> Система`.

Для точного SSID на Android также могут потребоваться Wi-Fi/location permissions и включённая
геолокация. Без них UI показывает `Wi-Fi (имя недоступно)`, а не вымышленное имя сети.

## Crash-safe state

Нужно хранить небольшой файл состояния:

```text
lastStartTime
lastStopReason
lastCrashReason
restartCount
lastActiveRoute
lastProfile
```

После запуска приложение может объяснить:

```text
Прокси был перезапущен системой 2 минуты назад.
Последняя причина: service killed.
```

Owner/VPS credentials хранятся отдельно через Android Keystore и не зависят от process state.
Обычное обновление APK с той же подписью не очищает их; переустановка с удалением данных или
другая подпись считаются новым владельцем устройства.

## Ложный Active

Состояние `Активен` запрещено показывать, если:

- локальный порт не слушает;
- сервис умер;
- нет ни одного доступного маршрута;
- active route несколько раз подряд не проходит health-check;
- приложение не может принять новое локальное подключение.

В этих случаях показывать:

```text
Переподключение
```

или

```text
Нет рабочего маршрута
```

## Тесты надежности

Перед релизом проверять:

- запуск и остановку;
- перезапуск приложения;
- блокировку экрана;
- смену Wi-Fi на мобильную сеть;
- смену мобильной сети на Wi-Fi;
- включение режима энергосбережения;
- убийство процесса через ADB;
- перезагрузку телефона;
- обновление debug/release APK поверх той же подписи с проверкой сохранённых Relay/owner данных;
- отказ от notification/battery/autostart шагов и сохранение предупреждения;
- работу после 30 минут простоя.
