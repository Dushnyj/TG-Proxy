# Участие в разработке TG Proxy

## Перед началом

1. Проверьте существующие issues.
2. Для крупного изменения сначала опишите проблему и предполагаемый контракт.
3. Не объединяйте в одном pull request несвязанные исправления.

## Локальная проверка

```bash
./gradlew testDebugUnitTest lintDebug assembleDebug --no-daemon
```

Подробная настройка окружения: [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md).

## Требования к изменению

- новый runtime-контракт покрыт unit/instrumented-тестом;
- UI проверен на узком экране, крупном шрифте и в светлой/тёмной теме;
- настройки сохраняются атомарно и не ломают существующие профили;
- route health не выдаёт TCP/HTTP проверку за Telegram MTProto proof;
- изменения формата хранения имеют совместимую миграцию;
- пользовательский текст объясняет действие без внутренних exception/log строк;
- обновлены README и профильные документы.

## Коммиты и pull request

Пишите небольшие императивные сообщения, например:

```text
fix: keep relay owner mapping during retry
docs: add VPS setup troubleshooting
```

В PR опишите причину, реализацию, тесты и визуальную проверку. Для UI приложите обезличенные
скриншоты до/после.

## Секреты и пользовательские данные

Перед коммитом проверьте `git status`, `git diff --check` и историю secret scanner. Используйте
только `relay.example.com` и RFC 5737 IP. Не добавляйте ADB-логи, диагностические ZIP, реальные
домены/VPS, токены, пароли, keystore или скриншоты аккаунтов.

Полная модель: [docs/PRIVACY_AND_SECRETS.md](docs/PRIVACY_AND_SECRETS.md).
