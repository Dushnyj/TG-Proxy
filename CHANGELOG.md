# Changelog

Все заметные изменения TG Proxy фиксируются в этом файле.

## [1.2.0] - 2026-08-27

### Telegram topology и маршрутизация

- MTProto handshake принимает будущие production/test DC и сохраняет знак DC как признак
  media; решение о доступности принимает конкретный route, а не общий hardcoded-фильтр.
- Direct и Cloudflare WebSocket больше не создают ложные `kws203`/`kws204` и не подменяют
  неизвестный DC другим. Для DC1-5 Direct гоняет встроенный bootstrap IP с актуальным DNS
  официального WebSocket hostname и запоминает фактического победителя. Проверка custom
  Cloudflare также больше не требует несуществующий `kws203`; Worker продолжает отдельно
  проверять свой известный raw DC203 mapping.
- VPS Relay согласует protocol, features, topology revision и реально доступные DC через
  `/capabilities`. Старый Relay без endpoint считается legacy static-map сервером и не получает
  ложные кандидаты для неизвестных DC.
- Для каждого сетевого профиля добавлены независимые выключатели Direct, VPS Relay, Worker,
  своего и публичного Cloudflare. Отключение активного route прекращает только его сессии и
  немедленно запускает корректный fallback; режим `Только Direct` доступен одной кнопкой.
- Независимый `Отклик MTProto` использует фактический endpoint активного route и настоящий
  `req_pq/resPQ`, поэтому не зависит от того, открыт ли Telegram в момент проверки.

### VPS Relay, media и совместимость

- Android 1.2.0 устанавливает Relay 1.2.0 с multiple-endpoint topology, endpoint health/cooldown,
  bounded race, IPv4/IPv6, произвольными портами и ролями regular/media/CDN/static.
- Добавлены подписанные Ed25519 topology bundles с atomic last-known-good cache, TTL, revision,
  monotonic generation, backoff/jitter и проверками размера, количества DC/endpoints и публичных
  адресов. Неизвестный DC может инициировать ограниченное on-demand обновление Relay.
- WebSocket protocol v2 строго валидирует `dc`, `test` и `media`; сохранена совместимость с
  `binary`/legacy-клиентами. `/test-routes` честно маркируется как `TCP_ONLY`, после чего Android
  отдельно выполняет MTProto proof.
- Исправлено длительное отключение VPS Relay: выключенный route не участвует в новых гонках, а
  уже открытые Relay-сессии закрываются без остановки Direct/Cloudflare-соединений.

### Владелец, импорт и интерфейс

- Владелец Relay видит первый/последний сеанс устройства, модель, версии приложения/Android и
  GeoIP; устройство можно отключить, заблокировать и разблокировать без отзыва всего token.
- Ссылка подключения всегда строится из выбранного Relay host/port/path, а не из встроенного
  домена. Единое меню предлагает ссылку, QR, системный Share и файл; secret остаётся во fragment.
- Настройки разделены на вкладки `Подключение`, `Маршруты`, `Relay`, `Система`, `О приложении`.
  Диалоги owner/tokens/devices/share получили Material-поверхности, нормальную иерархию и
  touch-target не меньше 48 dp в светлой и тёмной темах.
- `Сохранить Relay` теперь сразу фиксирует корректно заполненную конфигурацию, а длительная
  проверка Telegram DC запускается только отдельной кнопкой `Тест`. Результат capability
  negotiation больше не делает неизменённую форму ложным «несохранённым» Relay и не блокирует
  выход из настроек.
- Добавлены failure-injection matrix, доказательная документация Telegram topology и отдельное
  whitelist-only исследование; whitelist transport в production-код намеренно не добавлялся.
- В автонастройке собственный домен теперь вводится обычным полем; найденные на VPS адреса
  вынесены в отдельный прокручиваемый bottom sheet. Подпись поля больше не пересекает рамку,
  а выбор найденного адреса сразу открывает read-only план. Если DNS или web stack не подходят,
  этап 3 показывает причины и блокирует применение без изменения сервера. Можно указать любой
  домен/поддомен с корректной A/AAAA-записью, независимо от DuckDNS и текущих сайтов VPS.
- SSH-аудит и установщик больше не требуют Ubuntu/systemd: добавлены Linux package managers
  apt/dnf/microdnf/yum/zypper/apk/pacman/xbps/Portage, службы systemd/OpenRC/runit/SysV и
  переносимый fallback, а также расширенное сопоставление release-архитектур.

### Публичный репозиторий и поддержка

- Добавлены связанные инструкции первого запуска, фоновой работы, выбора VPS, DuckDNS,
  автонастройки, owner tokens, ссылки/QR/импорта, диагностики, разработки и релизов.
- README получил обезличенные экраны чистой установки; формы Issues требуют полный
  диагностический ZIP и запрещают публикацию SSH/token/персональных данных.
- Добавлены CI, Dependabot и full-history Gitleaks workflow. Production fixtures заменены
  `example.com` и RFC 5737 адресами.

## [1.1.2] - 2026-08-27

### Стабильный Wi-Fi-профиль после фонового перезапуска

- Приложение больше не заменяет известный SSID техническим `wifi:opaque:*`, когда Android
  временно скрывает сведения о той же Wi-Fi-сети при фоновом запуске или серии системных
  callbacks. Маршрут, приоритет и статистика продолжают использовать правильный профиль.
- Реальная смена точки подключения по-прежнему создаёт или выбирает новый профиль; старый
  SSID не переносится на другую сеть. Когда имя временно скрытой сети снова становится
  доступно, технический профиль автоматически повышается до точного SSID.
- Начальное подключение фиксируется до регистрации системного network callback, поэтому
  первый callback уже подключённой сети не считается ложным переходом между сетями.

## [1.1.0] - 2026-08-27

### Фоновая работа и сеть

- Добавлен пошаговый помощник непрерывной работы: запуск после перезагрузки, уведомления
  foreground service, исключение из оптимизации батареи, OEM-автозапуск и геолокация для
  точного SSID. После обновления состояние проверяется снова; отказ оставляет явное
  предупреждение о риске остановки прокси.
- Намерение «прокси включён» восстанавливается через sticky service, boot/package-replaced
  receiver, watchdog и резервный recovery alarm. Экран телефона при проверках не блокируется,
  а его пользовательская настройка stay-awake не изменяется.
- Удалено вымышленное имя Wi-Fi вида `Wi-Fi • 174D`: при доступных разрешениях показывается
  реальный SSID, иначе честное `Wi-Fi (имя недоступно)`. Старые сгенерированные подписи
  автоматически мигрируют.

### VPS Relay и права владельца

- SSH-данные, admin token и известные client secrets владельца сохраняются через Android
  Keystore и переживают обновление приложения с той же подписью; Android backup для них
  запрещён. Удалённая установка не начинается, пока owner-данные не записаны локально.
- Только устройство с сохранённым admin token видит owner-панель: список токенов, создание,
  отзыв с закрытием активных сессий и список известных устройств с маркой, моделью, версиями
  приложения/Android и GeoIP-страной/городом.
- Создание токена транзакционно: при ошибке локального сохранения приложение отзывает его на
  сервере; если rollback не удался, секрет показывается один раз для аварийного сохранения.
- Одна кнопка «Поделиться Relay» открывает выбор: кликабельная HTTPS-ссылка, QR-код,
  системное меню или файл. В payload входит только client token; SSH/admin-доступ не
  экспортируется. Импорт всегда показывает окно «Добавить новое подключение VPS Relay».
- HTTPS share link хранит payload после `#`, поэтому client token не попадает в HTTP-запрос и
  access log. Landing page Relay открывает приватную `tgproxy://`-ссылку приложения.
- Auto-setup/upgrade получил точный backup/rollback состояния, конфигурации, unit/drop-in,
  reverse proxy, UFW, каталогов, системного пользователя и группы. Старые systemd units
  усиливаются `Restart=always`, бесконечным start-limit, stop timeout и `LimitNOFILE`.

### Маршрутизация, медиа и интерфейс

- Раздел `Настройки -> Подключение` сгруппирован по профилю, стратегии маршрута, VPS Relay,
  Cloudflare/Worker и сворачиваемым расширенным локальным параметрам.
- Зафиксированы понятные приоритеты Auto/Direct/Cloudflare/Relay. В режиме «Cloudflare первым»
  собственный Cloudflare-домен и Worker идут раньше публичного пула.
- Main/media и каждый DC сохраняют раздельную статистику; WebSocket ограничивает размер
  сообщения, корректно собирает fragmentation, отвечает на ping/pong и передаёт полные
  MTProto packets, что исключает обрезание крупных медиа-ответов.
- Поле «Пинг» переименовано в «Отклик MTProto»: измеряется полный TCP/TLS/WebSocket/Relay путь
  до валидного Telegram `resPQ` раз в 30 секунд. Ошибка вспомогательной проверки не стирает
  подтверждённую задержку работающего маршрута.

## [1.0.8] - 2026-08-27

### Проверка Relay без ложного rollback

- Production DC1–5/DC203 по-прежнему обязательно проверяются end-to-end отдельно для main и media; временный сбой получает одну повторную попытку и остаётся причиной rollback, если повторяется.
- Telegram test environment проверяется отдельной последовательной advisory-фазой. Недоступность внешнего test DC больше не откатывает исправный production Relay и явно показывается как предупреждение.
- Локальное закрытие WebSocket по истечении абсолютного probe deadline теперь диагностируется как `telegram probe deadline exceeded`, а не как вводящий в заблуждение `Socket closed`.

### Стабильный runtime и достоверный главный экран

- Периодическое обновление UI больше не записывает сетевой профиль каждую секунду, не запускает повторное применение runtime-конфигурации и не обновляет foreground notification в обход минутного лимита.
- Повторные Android `onCapabilitiesChanged` без смены сети стали read-only; отсутствующий или повреждённый MTProto secret восстанавливается один раз и остаётся стабильным между reload.
- Ошибка отдельного фонового ping больше не перекрывает подтверждённую first-byte latency рабочего Telegram-маршрута красным `error`.
- Результаты ping привязаны к route+endpoint и уникальному attempt token: поздний результат старого маршрута, домена или service generation отбрасывается.
- Status, route, endpoint, profile, quality и ping одного UI tick рисуются из одного diagnostics snapshot.
- Route key, endpoint и время последнего подтверждённого трафика публикуются одним атомарным snapshot; upload-трафик теперь также освежает живость маршрута.
- Дополнительная диагностика test-account маршрутов сохраняет флаг test для Direct `/apiws_test`, Worker и VPS Relay.

## [1.0.7] - 2026-08-26

### Постоянная работа в фоне

- Явное намерение пользователя держать прокси включённым сохраняется синхронно и восстанавливается после обычного завершения процесса, перезагрузки и обновления приложения.
- Добавлены контролируемый sticky restart, резервный alarm восстановления и диагностика причины предыдущего завершения процесса.
- Watchdog продолжает проверять listener каждые 3 секунды, но foreground-уведомление обновляется не чаще раза в минуту: устранены десятки тысяч лишних notification updates в сутки на MIUI.
- Устаревший Smart Sleep больше не останавливает прокси при выключении экрана.
- Настройки получили помощник фоновой работы для исключения из оптимизации батареи и OEM-настроек автозапуска без автоматического открытия системных окон.

### Маршрутизация, медиа и смена сети

- Main- и media-соединения маршрутизируются и оцениваются отдельно; гонка маршрутов отправляет один и тот же первый реальный MTProto-запрос и выбирает победителя только после первого ответа Telegram, а не после одного HTTP `101`.
- Исправлено преждевременное закрытие туннеля после EOF локального upload-направления: ответы, голосовые, изображения и видео продолжают приниматься.
- Добавлена end-to-end поддержка Telegram test DC `±10001..±10003`: Direct использует `/apiws_test`, Worker и VPS получают test target, а Cloudflare для test DC не выбирается.
- Исправлен hostname custom Cloudflare для media/DC203: используется тот же `kws<dc>.<base-domain>`, что и в `tg-ws-proxy`.
- Добавлены общий бюджет подключения, ограниченные таймауты попыток, half-open recovery и более точные cooldown для TLS, WebSocket, HTTP 429 и Telegram protocol ошибок.
- Смена оператора/Wi-Fi применяет новый runtime-конфиг атомарно; callback сети debounced и всегда перечитывает фактическую default network.
- Wi-Fi со скрытым SSID получают приватный install-scoped идентификатор по доступному BSSID/network ID; полностью редактированный Android-профиль остаётся стабильным между reconnect и заново проверяет маршруты при каждой смене сети.
- Cloudflare warm pool ограничен по возрасту и больше не создаёт стартовый burst по всем DC; HTTP 429 изолирован по сетевому профилю.
- Ручные проверки Cloudflare и Worker теперь выполняют настоящий зашифрованный Telegram `req_pq/resPQ` probe для main и media каждого DC.
- Intermediate MTProto корректно маскирует служебный high bit длины; Direct-only режим больше не исключает media DC2.
- Handshake, первый полный MTProto packet, первый ответ Telegram и WebSocket-запись получили абсолютные deadlines, которые нельзя продлевать передачей по одному байту или control frames.
- Listener регистрирует принятый socket до запуска client thread, ограничивает повторные accept-ошибки и отдаёт восстановление watchdog вместо CPU hot loop.
- Один общий connect budget больше не удваивается при смене network generation; stop/reset физически отменяют устаревшие попытки без ложного cooldown.
- Несколько одновременных сессий одного маршрута учитываются независимо: сбой одной не скрывает живую и не ставит здоровый route в cooldown.
- Штатное завершение короткой Telegram/media-сессии сохраняет последний проверенный маршрут, поэтому статус больше не прыгает в `degraded` после каждого закрытия соединения.
- Half-close drain ограничен жёстким таймаутом, а зависшие локальные и upstream записи физически прерываются.

### VPS Relay, импорт и экспорт

- Relay-профили получили стабильные идентификаторы с учётом credential, атомарное сохранение вместе с привязкой к сети и независимые токены для одинакового endpoint.
- Импорт сначала проверяет `/healthz`, `/version` и все обязательные Telegram DC, и только после успеха применяет профиль целиком.
- Внешняя `tgproxy://import` ссылка, включая зашифрованную, после ввода пароля показывает безопасное превью и требует подтверждения; имя импортированного сетевого профиля сохраняется.
- Экспорт теперь действительно поддерживает копирование, файл, системный Share и QR; удалённый Relay не восстанавливается из legacy-полей.
- Автонастройка устанавливает Relay `1.0.5`, переносит custom WebSocket path и test DC map, проверяет SHA-256, версию и конфиг, ждёт рабочий systemd unit и откатывает точную транзакцию, а не последний чужой backup.
- Первый SSH host key требует явного подтверждения SHA-256 fingerprint; сменившийся ключ блокирует настройку до явного сброса пользователем.
- Android backup отключён, чтобы MTProto secret и raw Relay tokens не попадали в системную резервную копию.
- Добавление токена сохраняет все остальные поля существующего Relay config; update объединяет недостающие DC/test DC, не затирает пользовательские значения и синхронно обновляет `publicUrl`/WebSocket path.
- Raw Relay token больше не передаётся binary через process argv: SHA-256 вычисляется в setup shell.
- Rollback удаляет только файлы, созданные своей транзакцией, восстанавливает точные изменённые пути и прежнее состояние systemd; ошибка rollback больше не проглатывается.
- Rollback также восстанавливает UFW rules и удаляет только созданные этой установкой пользователя и каталоги.
- Проверка Relay проходит полную production/test и main/media матрицу в одном абсолютном бюджете и после deploy сверяет точную версию `1.0.5`.
- Relay export из интерфейса теперь всегда AES-GCM-зашифрован паролем; raw bearer token не показывается в Share, QR или файле.
- Импорт и обычное сохранение фиксируют transport, Relay, имя сетевого профиля и route preference одной транзакцией SharedPreferences; удаление Relay/профиля также больше не оставляет частичное состояние.

## [1.0.6] - 2026-06-30

### Надёжность прокси

- Добавлена явная state machine сервиса: `Starting`, `Active`, `Degraded`, `Retrying`, `Dead`.
- Главный экран и foreground-уведомление больше не показывают `Active`, если движок не слушает локальный порт или нет свежего подтверждённого маршрута.
- Watchdog сервиса перезапускает engine, если foreground service жив, но локальный proxy listener умер.

### VPS Relay и профили

- VPS Relay хранится как отдельная сущность: добавлено удаление Relay, сохранение только валидных Relay и привязка к профилям сети.
- Runtime-маршрутизация больше не использует legacy `vps_relay_*` prefs как fallback.
- Импорт Relay создаёт сохранённую запись, а не только временно заполняет форму.

### Маршрутизация и диагностика

- Добавлен generation/session guard для маршрутов: события старых соединений после смены сети больше не портят статистику нового профиля.
- Сброс диагностики очищает route evidence, active route, ping gate и последний auto-ping, а не только текстовый лог.
- GitHub Actions теперь проверяют `push main` и `pull_request main`; release jobs запускаются только для tag/manual release и checkout-ят нужный tag.

## [1.0.5] - 2026-06-05

### Маршрутизация

- MTProto parser больше не ограничивает DC фиксированным списком `1-5/203`; он проверяет handshake, secret, protocol tag и корректный номер DC.
- Решение о поддержке DC перенесено в Route Engine: известные raw Telegram DC и явные direct mapping строят маршрут, неизвестные DC закрываются с понятным `unsupported dc`.
- В route-логах добавлены `dcRaw`, нормализованный `dc` и флаг `media`, чтобы отличать `203 main` от `-203 media` и корректно разбирать новые Telegram DC.
- Диагностика показывает DC203 как обычный доступный маршрут для `main` и `media`, без искусственного статуса `media only`.
- Проверка VPS Relay `/test-routes` теперь использует фактическую карту DC из настроек, а не встроенную default-карту.

## [1.0.4] - 2026-06-05

### Маршрутизация и медиа

- Исправлена загрузка медиа через VPS Relay для Telegram DC203: Android больше не отвергает DC203 handshake, а Relay получает raw Telegram endpoint `91.105.192.100`.
- После первичного MTProto handshake локальный socket Telegram больше не закрывается по read timeout во время долгой загрузки медиа.
- Route ping теперь проверяет полный путь до Telegram через минимальный MTProto probe, а не только доступность WebSocket/Relay endpoint.
- Статистика и ошибки VPS Relay разделены по DC и типу соединения, чтобы медиа-сбои не ломали общий статус маршрута.

### Импорт, обновления и автонастройка

- Импорт Relay из QR/текста применяет настройки к выбранному профилю сети, а не молча к текущему auto-профилю.
- Deeplink из текста экспорта корректно извлекается даже если вокруг него есть поясняющий текст.
- Обновление APK проверяет, что системный installer реально применил новую версию.
- Автонастройка VPS и подключение к существующему Relay добавляют DC203 в `dcMap` и сохраняют рабочие права конфига.

## [1.0.3] - 2026-06-05

### VPS Relay

- Исправлен route check для VPS Relay: Android проверяет весь Relay-маршрут через WebSocket с авторизацией, а не обычный TCP-пинг порта.
- Автонастройка VPS теперь пишет raw Telegram DC map для Relay вместо Flowseal/WebSocket endpoint.
- При подключении к уже установленному Relay автонастройка чинит устаревший DC map, добавляет недостающие DC и сохраняет права конфига так, чтобы systemd-сервис мог его читать.
- Улучшено восстановление route-встраивания для Docker Caddy и существующих Relay-инсталляций.

### Диагностика

- Логи route/client/session пишутся в системный logcat при активном прокси.
- Счетчики закрытия клиентских сессий больше не смешивают глобальный трафик с трафиком конкретной сессии.

## [1.0.0] - 2026-06-02

### Стартовый релиз

TG Proxy — Android-приложение, которое поднимает локальный MTProto-прокси для Telegram на телефоне. Пользователь запускает приложение, добавляет локальный прокси `127.0.0.1:1443` в Telegram через готовую ссылку и работает без отдельного клиентского приложения.

### Основные возможности

- локальный MTProto-прокси с подключением Telegram одной ссылкой `tg://proxy?...`;
- маршрутизация Telegram-трафика через WebSocket-подход, вдохновленный Flowseal/tg-ws-proxy;
- Cloudflare Proxy и Cloudflare Worker как резервные маршруты для стабильной загрузки медиа;
- настройка Telegram DC -> IP, secret, локального IP и порта;
- проверка пинга, счетчики Up/Down и аптайм на главном экране;
- foreground-уведомление с адресом, трафиком и кнопкой запуска/остановки;
- автозапуск при открытии приложения и после включения устройства;
- проверка обновлений из GitHub Releases с прогрессом скачивания;
- локализация на русский и английский, светлая/темная тема и режим как в системе.

### Релизные файлы

GitHub Actions публикует подписанные APK для `arm64-v8a`, `armeabi-v7a`, `x86_64`, универсальную сборку и `SHA256SUMS.txt`.
